LORE — NATAL CHARTS  ·  Setup
==========================================================

This is the short version. README.md has the full account of everything
below ("Building from Source", "Data Files", "Calculation Settings").

PREREQUISITES
──────────────────────────────────────────
  • Windows 10 version 1809 or later, 64-bit
  • .NET 10 SDK
  • Visual Studio 2019/2022 Build Tools with the "Desktop development with
    C++" workload (needed once, to compile sweph.dll)
  The Windows App SDK and the other packages are fetched by NuGet on restore.

STEP 1 — COMPILE SWEPH.DLL  (one-time)
──────────────────────────────────────────
  The Swiss Ephemeris source and the ephemeris data files the app ships are
  bundled in Data\swisseph-2.10.3bfinal\.  From the project root:

      .\Build-SwephDll.ps1

  This produces  Native\sweph.dll.  If the script can't find Visual Studio,
  install the free "Build Tools for Visual Studio 2022" from
  https://visualstudio.microsoft.com/downloads/ and re-run.

STEP 2 — BUILD AND TEST
──────────────────────────────────────────
      dotnet restore
      dotnet build -c Release -r win-x64
      dotnet test tests\Lore.Tests

  Or open Lore.csproj in Visual Studio 2022 (17.11+). The .csproj copies
  sweph.dll and the .se1 ephemeris files to the build output by itself.

  The same build-and-test runs on GitHub for every push
  (.github\workflows\ci.yml).

STEP 3 — RELEASE
──────────────────────────────────────────
  Set the version in one place: <Version> in Lore.csproj (and the file
  names at the top of README.md). Then double-click  release.bat  (or run
  it). It builds sweph.dll if it is missing, runs the tests (a failing
  test stops the release), publishes the self-contained app, runs the
  personal-data safety gate, and compiles the installer:

      artifacts\LoreSetup-<version>.exe
      artifacts\Lore-<version>-portable\

  One-time: install the Inno Setup compiler —
      winget install --id JRSoftware.InnoSetup -e

  The two halves can be run on their own:
      .\scripts\build-portable.ps1     (portable folder only)
      .\scripts\build-installer.ps1    (portable folder + installer)

  The installer is unsigned, so Windows SmartScreen warns the first time —
  "More info" → "Run anyway".

OCCASIONAL
──────────────────────────────────────────
  .\scripts\build-icons.ps1            app icon (requires ImageMagick)
  python scripts\build-cities.py       Data\cities.json from the simplemaps CSV
  scripts\build-hospitals.bat          Data\hospitals.json (Wikidata + OpenStreetMap)
  python scripts\build-swetest-reference.py
                                       the swetest comparison values for the tests

  Their outputs are committed, so a normal build or release never needs them.

TROUBLESHOOTING
──────────────────────────────────────────
  "DLL not found" at runtime
      → Run Build-SwephDll.ps1 first; verify Native\sweph.dll exists.

  "Ephemeris file not found" / SE_ERR in chart
      → Rebuild the project so the .se1 files are copied to the output
        Assets\Ephemeris\ folder (the .csproj handles this automatically).

  Calculation error for pre-1800 birthdays
      → The _12 ephemeris files are required; they are included in the
        Data folder and copied automatically. Check the build output.

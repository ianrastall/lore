LORE — NATAL CHARTS  ·  Setup
==========================================================

PREREQUISITES
──────────────────────────────────────────
  • .NET 10 SDK
  • Windows App SDK 1.7+  (via NuGet, fetched automatically on restore)
  • Visual Studio 2019/2022 Build Tools with "C++ Desktop" workload
    (needed once to compile sweph.dll — the Swiss Ephemeris C library)

STEP 1 — COMPILE SWEPH.DLL  (one-time)
──────────────────────────────────────────
  The Swiss Ephemeris source and all ephemeris data files are bundled in
  Data\swisseph-2.10.3bfinal\.  Run the build script from the project root:

      .\Build-SwephDll.ps1

  This produces  Native\sweph.dll  (~600 KB).  If the script can't find
  Visual Studio, install the "Build Tools for Visual Studio 2022" package
  (free) from https://visualstudio.microsoft.com/downloads/ and re-run.

STEP 2 — BUILD THE APP
──────────────────────────────────────────
  From the project root:

      dotnet restore
      dotnet build -c Release -r win-x64

  Or open Lore.sln in Visual Studio 2022 (17.11+).

  The .csproj automatically copies sweph.dll and all needed .se1 ephemeris
  files to the build output — no manual file placement required.

STEP 3 — PORTABLE BUILD (to hand to someone else)
──────────────────────────────────────────
  Produce a self-contained folder that runs with no install, no .NET, and no
  VC++ redistributable required on the target machine:

      .\scripts\build-portable.ps1

  Output: artifacts\Lore-0.2-portable\  — zip it and send it; the recipient
  just runs Lore.exe.

STEP 4 — INSTALLER  (double-click install, Start-menu entry)
──────────────────────────────────────────
  Produces a single LoreSetup-<version>.exe that installs Lore per-user (no
  admin prompt), adds a Start-menu shortcut, and registers a clean uninstall
  entry in Add/Remove Programs.

  One-time: install the Inno Setup compiler —
      winget install --id JRSoftware.InnoSetup -e

  Then, from the project root:
      .\scripts\build-installer.ps1

  Output: artifacts\LoreSetup-<version>.exe  — attach it to a GitHub Release;
  the recipient downloads and double-clicks. (Unsigned, so Windows SmartScreen
  shows "Windows protected your PC" the first time — click "More info" →
  "Run anyway". No certificate or extra runtime needed.)

  The installer script wraps the self-contained build from Step 3, so nothing
  else must be installed on the target machine.

  To regenerate the app icon (indigo/gold "L"), run:

      .\scripts\build-icons.ps1     (requires ImageMagick)

CELEBRITY DATA
──────────────────────────────────────────
  celebrities.json contains ~110 entries across 12 categories.
  Each entry includes:
      birthDate          ISO date, e.g. "1935-01-08"
      birthTime          "HH:mm" local time, or null
      birthTimeKnown     true/false
      latitude/longitude birth location (decimal degrees)
      utcOffsetHours     fixed UTC offset — fallback only (see below)
      timeZoneId         IANA zone id, e.g. "Europe/London" (optional)
      bio                one-sentence description

  The birth instant is resolved by Services/BirthTimeResolver: it prefers
  timeZoneId (or, if absent, a lat/lon lookup) and applies the HISTORICAL,
  DST-aware offset in force on the birth date via the IANA tz database
  (NodaTime). utcOffsetHours is used only when no zone can be resolved.
  Entries without timeZoneId are backfilled from their coordinates, so the
  bundled corpus gets correct DST automatically.

  birthTimeKnown=false → chart uses 12:00 noon; ASC/house cusps
  will be unreliable for those charts.

CITY DATABASE
──────────────────────────────────────────
  cities.json powers the Add-Chart city search (autofills lat/lon, the IANA
  timeZoneId, and a fallback UTC offset). It is generated from the simplemaps
  world-cities CSV, which has no timezone data — the build script maps each
  city's lat/lon to its IANA timezone (stored as "tz") and also bakes in the
  standard non-DST offset ("utc") as a display/fallback value.

  To regenerate (e.g. after updating the simplemaps download):
      pip install --user timezonefinder tzdata      (one-time)
      python scripts\build-cities.py

  Output: Data\cities.json  (~50,250 cities, ~5.4 MB). The suggested UTC
  offset is standard time; the Add-Chart dialog lets the user adjust it
  (e.g. for a summer/DST birth) before saving.

  Attribution: city data © simplemaps.com "World Cities Database" (Basic),
  licensed CC BY 4.0 (https://simplemaps.com/data/world-cities).

HOUSE SYSTEM
──────────────────────────────────────────
  Placidus is the default.  Change the HouseSystem constant in
  Services\ChartService.cs to any letter Swiss Ephemeris accepts:
      'P'  Placidus   (default)
      'W'  Whole Sign
      'K'  Koch
      'E'  Equal

TROUBLESHOOTING
──────────────────────────────────────────
  "DLL not found" at runtime
      → Run Build-SwephDll.ps1 first; verify Native\sweph.dll exists.

  "Ephemeris file not found" / SE_ERR in chart
      → Rebuild the project so the .se1 files are copied to the output
        Assets\Ephemeris\ folder (the .csproj handles this automatically).

  Calculation error for pre-1800 birthdays
      → The _12 ephemeris files are required; they are included in the
        Data folder and copied automatically. Check the build output.
